# V0.7 Subscription Lifecycle (Phase 1)

Status: development capability, not a released ProxyFlow version.

Format compatibility details: [subscription-format-compatibility.md](./subscription-format-compatibility.md)

## Architecture

V0.7 Phase 1 keeps the existing persistence and compiler boundaries:

```text
Persistent Project / Graph
          +
Active runtime snapshot view
          ↓
Graph Compiler
          ↓
Universal IR
          ↓
Semantic Validator
          ↓
Target Compiler
```

Project and Graph remain the persistent source of truth. A subscription snapshot is runtime state. Remote nodes, snapshot IDs, diffs, refresh errors, cache metadata, and remote credentials never enter Project JSON or Graph node configuration. Target compilers continue to consume only Universal IR and never fetch or parse subscriptions.

## Runtime state

Runtime state is intentionally orthogonal:

- refresh: `idle | loading | succeeded | failed`
- active snapshot: `none | usable | empty`
- freshness: `fresh | stale`
- latest outcome: `success | failure | superseded | empty-confirmation-required`

An immutable committed snapshot records its source, schema and identity algorithm versions, timestamps, content hash, detected format, normalized parse result, quality, source configuration fingerprint, and safe HTTP metadata. Raw remote response bodies are candidate-only and are not persisted.

Candidate quality is classified before commit:

- `usable`: at least one Ready endpoint; Partial and Unsupported entries may coexist.
- `empty`: a recognized valid format contains zero nodes.
- `invalid`: blank content, unsupported or fatal parse results, or detected nodes with no Ready endpoint.

Only `usable` and `empty` snapshots can become active.

## Refresh and Last Known Good

Manual Refresh builds and validates a candidate, computes its diff, and atomically replaces the active runtime snapshot. The graph immediately derives a new IR from the committed active view.

Last Known Good is the most recently committed usable snapshot, or an empty snapshot explicitly confirmed by the user. A failed refresh updates only attempt/failure status and its secret-safe diagnostic. It does not clear active nodes, change the last successful timestamp, or interrupt Filter, Sort, Rename, Dedupe, Merge, Limit, Strategy, Chain, Preview, or target compilation.

Each source has a monotonic request generation and an `AbortController`. Starting a newer refresh aborts the previous request when possible. Every candidate checks its generation before diff and commit, so a late older response cannot replace a newer result.

## Local runtime cache

Normalized active URL snapshots are cached in IndexedDB database `proxyflow.runtime.v1`. Runtime storage schema version `1` is independent of Project Schema version `2`.

The cache scope is:

```text
projectId + sourceId + SHA-256(source configuration)
```

Changing a subscription URL immediately removes the old active runtime view. A cache for the old fingerprint cannot hydrate the new source configuration.

Hydration reads each source independently. A missing cache produces `Not loaded`; a malformed or unreadable entry is isolated to that source and cannot corrupt the Project or clear other subscription caches. A successful network refresh becomes active before best-effort persistence. If an IndexedDB write fails, the new in-memory result stays active and the UI warns that a reload may recover an older cached snapshot.

Subscription cache is stored locally in this browser and may contain proxy credentials. It is not uploaded by ProxyFlow.

订阅缓存保存在当前浏览器本地，其中可能包含代理凭据。ProxyFlow 不会将其上传。

The cache is not described as encrypted or password protected. `Clear local snapshot` confirms the operation, removes the current source's persisted and active runtime snapshot, and leaves its Project node, URL, configuration, and graph topology unchanged. `Delete subscription source` is separate: it removes the graph node and connected edges, cancels and invalidates pending work, removes runtime state, and deletes all cache entries scoped to that project and source. Late hydration, refresh responses, and cache writes cannot recreate the source.

## Diff and identity

Subscription continuity identity is separate from the deduplication fingerprint. It canonicalizes protocol, lowercase host, numeric port, transport intent, and security intent while excluding names and display metadata from primary identity.

VMess, VLESS, and TUIC use an opaque source-scoped UUID principal. HTTP and SOCKS can use username as an auxiliary principal. Other protocols use a source-scoped connection anchor. Ambiguous matches are reported as `SUBSCRIPTION_IDENTITY_AMBIGUOUS` and safely degrade to Removed plus Added instead of guessing Changed.

The deterministic pure diff reports Added, Removed, Changed, and Unchanged. Changed entries may contain Renamed, AuthenticationChanged, ConnectionChanged, MetadataChanged, and ReadinessChanged subtypes. The UI shows labels such as `Authentication changed`; it never renders old/new passwords, UUIDs, credential hashes, raw endpoint JSON, or raw subscription URIs. The first successful refresh is shown as an initial baseline rather than a large Added list.

## Empty protection

A valid empty result can become the first active snapshot. When a non-empty active snapshot exists, an empty candidate is held pending and the current snapshot remains active. The confirmation dialog defaults focus to `Keep current snapshot`; closing it also keeps the current snapshot. Only `Apply empty snapshot` atomically commits zero nodes.

Blank responses are invalid and never enter this confirmation path.

## Refresh All

Refresh All processes enabled URL subscriptions only. Paste Content, local files, and disabled URL sources are skipped. A concurrency limiter runs at most three requests at once, while each source commits independently as soon as it succeeds. One failure cannot roll back or block another source, and the summary distinguishes failures that retained a previous snapshot.

## Freshness

A snapshot older than 24 hours is shown as stale. Staleness is a UI hint: it does not invalidate the snapshot, change endpoint readiness, block compilation, or clear downstream output. The threshold is fixed in Phase 1.

## Browser and CORS boundary

URL refresh uses direct browser Fetch. Servers must allow the browser origin through CORS. ProxyFlow does not provide a public CORS proxy. When the browser blocks a request, the UI recommends Paste Content, Local File, or a URL with compatible CORS headers. Diagnostics show safe summaries such as `HTTP 502` and never include a token-bearing URL or response body.

## Phase boundary

Phase 1 includes manual Refresh, Refresh All, status, candidate/active snapshots, LKG, IndexedDB hydration, diff, race protection, downstream recompute, format detection/import, clear local snapshot, delete-source cleanup, and empty-result confirmation.

Phase 1 does not include scheduled or background refresh, automatic retry, history, rollback, notifications, ETag conditional requests, a backend, cloud sync, a public CORS proxy, proxy speed testing, GeoIP, or a third target.
