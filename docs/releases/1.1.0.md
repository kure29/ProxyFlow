# ProxyFlow 1.1.0

ProxyFlow 1.1.0 is a stable minor release with Mihomo and Surge as the two
supported production export targets. Mihomo remains the default target for new
Projects; sing-box official export remains paused.

## Highlights

### Surge is now supported

Surge `.conf` preview, copy, and export are available through a documented,
fail-closed compatibility subset. Real Surge client import and proxy-traffic
acceptance passed with a real subscription Project.

### Better mixed-subscription compatibility

Surge evaluates the endpoints that participate in active strategies. Usable
members of a replaceable pool remain exportable when incompatible candidates
are skipped and reported in an aggregated warning. Explicit unsupported intent
continues to fail closed; Project and Graph data are never rewritten to force
compatibility.

### First-party service routing

The release includes first-party service rule assets for OpenAI, Claude, Google,
Gemini, YouTube, Netflix, Disney+, Telegram, GitHub, and Steam.

### Better diagnostics

Target compatibility messages are human-readable while stable technical codes
remain available for inspection and automation. Inactive targets report their
available state instead of showing a misleading checking spinner.

## Compatibility notes

Surge does not support every protocol or semantic combination. Unsupported
semantics remain fail closed, including VLESS, VMess where exact intent cannot
be proven, some Load Balance modes, advanced DNS combinations, and unproven
native `policy-path` formats. See [Surge Compiler](../surge-compiler.md) and
[Surge acceptance](../surge-acceptance.md) for the supported subset and
diagnostics.

## Upgrade

Self-hosted Stable installations continue to use the manager's stable channel:

```bash
/root/proxyflow.sh update
```

Managed Stable installations use `ghcr.io/kure29/proxyflow:latest`. Direct
Compose deployments can pin `ghcr.io/kure29/proxyflow:1.1.0` after the v1.1.0
container has been published.
